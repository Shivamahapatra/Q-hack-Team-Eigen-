# Contributing Guidelines - Team Eigen

## Branching Strategy
- Each team member must work on a dedicated branch named following the convention: `name/feature` (for example, `john/circuit-loader` or `shiva/benchmarking`).
- Never push directly to `main`.

## Commits
- Commit small, focused changes often with clear and descriptive commit messages.

## Pull Requests & Code Review
- To merge work into `main`, open a Pull Request (PR).
- Every PR must be reviewed and approved by at least one other team member before merging.
- Ensure all tests pass and documentation is updated before requesting review.
